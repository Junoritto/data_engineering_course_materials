## 강의 내용 정리
### RDD (Resilient Distributed Dataset)

1. Resilient (탄력성)
2. Distributed (분산성)
3. immutable (불변성)
    - immutable하기 때문에 백만개 데이터 중에 한개만 편집해야 해도 RDD를 새로 만들어야 함.
4. Lazy Evaluation (지연 연산) → 이거 때문에 spark가 optimazation 될 수 있는거임.
    - Transformation이 바로 실행되지 않고 쌓여 있다가, Action이 호출 될 때 실행됨.
    - 최적화된 실행 계획 (DAG)을 통해 효율적인 연산 수행

### Creating RDD

1. Parallelized collections
2. External datasets
3. Existing RDDs

### Transformation vs Action

- RDD에 Transformation을 하면 새로운 RDD가 나온다.
    - Transformation 예시 : map, lter, atMap, groupBy 등등
- RDD에 Action을 걸면 RDD가 아니다.
    - Action 예시 : collect, count, saveAsTextFile, reduce 등등

### Narrow & Wide Transformations

- Narrow Transformation
    - 파티션간 데이터 이동 없음
    - 네트워크 I/O 발생하지 않음
    - 병렬 처리에 유리
    - map, filter, flatmap 등등
- Wide Transformation
    - 파티션간 데이터 이동 발생
    - 네트워크 I/O 발생, 성능에 부담이 생김
    - 병렬 처리 어려움
    - Reduce 단계 필요
    - groupByKey, reduceByKey, sortByKey

→ 최대한 optimize 하기 위해 Wide Transformation을 최소화해야 한다. Wide Transformation을 사용할 때는 명확한 의도를 가지고 해야 한다.

### Shuffle

- 데이터가 불균형할 때 발생
- 데이터를 특정 방식으로 정렬해야 할 때
- 데이터를 집계하거나 조인할 때
- 메모리에 데이터를 다 담을 수 없을 때
- DAG에서 exchange 노드가 등장할 때

### DAG (Directed Acyclic Graph)

- Directed : 방향성이 있고
- Acyclic : 비순환성

### RDD vs Dataframe

- 웬만하면 Dataframe 사용하는 게 더 좋음.
- 저수준에서 직접 optimize할 때나 비정형 데이터를 처리할 때만 RDD가 유리
